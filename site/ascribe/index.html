Ascribe

Documentation written as code, checked like code, and built into a website, plain Markdown and JSON from the same files.

What it does

  • Write pages in Markdown, with a few directives for notes, steps, tabs and content that changes with the product or its version.
  • Check every link, include, phrase and code example as you type in VS Code, and again in CI, so the docs can't quietly break.
  • Build one set of files into a website with Astro, a plain Markdown copy of every page for AI assistants, and JSON.
  • Review a change to the docs as the pages a reader will see, not as a diff of Markdown.
  • Give AI coding agents the same checks, so what they write is held to the same rules as what you write.

Why a small studio makes a docs tool

Documentation drifts from the software it describes, one small change at a time, and nobody notices until a reader follows it into a wall. Ascribe treats docs the way code is treated, so the drift is caught where it starts. It is grown the way everything here is: slowly, a release at a time, with care.
