# Bryo Studio website

The site for `bryostudio.com`, built with Astro into plain static files:
HTML, stylesheets, and two small scripts (the theme toggle, and the home
page's riverbank). Netlify runs `npm run build` and publishes `dist/`.

The riverbank moves slowly and in steps: moss spreads over the stones a cell
at a time for a couple of minutes, then rests, and the river runs beneath. It
pauses when off screen or in a background tab, and anyone who prefers reduced
motion sees it still and fully grown.

Run `npm install` once after cloning. Then `npm run dev` serves the site at
`http://localhost:4321` and reloads on changes, and `npm run build` followed
by `npm run preview` serves exactly what Netlify will publish. The security
policy's headers only exist on Netlify (or `netlify dev`), so neither of
those enforces it.

## TypeScript

The functions, scripts and the site's `.ts` files are TypeScript, checked by
TypeScript 7 (`npm run typecheck`, the first half of `npm run build`, so a
type error fails the deploy). Netlify bundles the functions itself, Node
(22.22 or later) runs the scripts straight from `.ts`, and Astro builds the
site, so `tsconfig.json` allows only syntax Node can strip
(`erasableSyntaxOnly`: no enums, namespaces or parameter properties).

`.astro` files are not type-checked: `astro check` needs TypeScript's compiler
API, which TypeScript 7 lacks until 7.1. Add `astro check` to the build then.

## Telemetry

Games post batches of telemetry lines to `https://bryostudio.com/api/telemetry`
(`netlify/functions/telemetry.ts`; the request and replies are described at
the top of that file). The function checks every batch and writes it to the
`pizza_ambulance.telemetry` collection of the Atlas cluster. A game never
holds database credentials.

- **`MONGODB_URI`** is set in Netlify (Site configuration, Environment
  variables), scoped to Functions and marked secret. It connects as the
  Atlas user `telemetry-writer`, which may only read and write the
  `pizza_ambulance` database. It is never written in this repository.
- Each stored line keeps the game's fields and adds `_game`, `_install` (a
  random id per install), `_app` (the game's version), `_batch` and
  `_received`. A batch sent again is stored once.
- Refused whole: anything but POST, bodies over 512 KB, more than 500 lines,
  a line over 16 KB, unknown games or line kinds, field names starting with
  `$`, `_` or containing `.`. One address may post 30 times a minute.
- To check the whole path after a deploy:
  `npm run test:telemetry`. Its lines have an install id
  starting `test-`; delete them in Atlas with
  `{"_install": {"$regex": "^test-"}}`.
- Locally, `netlify dev` serves the site and the function on
  `http://localhost:8888` with the Netlify environment variables, and
  `npm run test:telemetry -- http://localhost:8888` posts to it.

The contact addresses are `hello@bryostudio.com` (footers, general contact)
and `privacy@bryostudio.com` (the privacy pages' requests), both Google Workspace aliases.

## Pages

Every page is in `src/pages/`, and its path is its address:
`src/pages/privacy/ascribe.md` is `/privacy/ascribe/`. `src/layouts/Base.astro`
gives every page the same head, header and footer; a page only supplies its
title, its description and its content. The header marks the current section
by the address (a privacy policy is under Privacy), the canonical link and
the sitemap follow from the address too, and `theme.js` adds the light/dark
button.

An Astro page:

```astro
---
import Base from "../layouts/Base.astro";
---
<Base title="Page title" description="One plain sentence about this page.">
  <h1>Page title</h1>
  <p>…</p>
</Base>
```

The title gets " · Bryo Studio" added; leave it out only on the home page.
`noindex` keeps a page out of search results and the sitemap (the 404 uses
it).

A Markdown page, such as a privacy policy:

```markdown
---
layout: ../../layouts/Markdown.astro
title: "Page title"
description: "One plain sentence about this page."
---

# Page title

Text in Markdown. HTML works too, for tables with captions and the classes below.
```

Markdown punctuation is left exactly as written (curly quotes are typed, not
converted), and headings get `id`s, so a section can be linked to.

### What `main.page` styles with no classes

`h1`, `h2`, `h3`, `p`, `ul`, `ol`, `li`, `strong`, `a`, `hr`, `code` and
`table` (with `thead`/`th`/`td`/`caption`; wide tables scroll inside
themselves on phones) are all styled for long reading at about 65 characters
a line. Two small classes for policy pages:

```html
<p class="updated">Last updated: 17 October 2026</p>

<div class="note">
  <p>A short boxed aside, such as a plain-English summary.</p>
</div>
```

Other classes in `styles.css` (`.lede`, `.eyebrow`, `.card`, `.status`,
`.button`, `.makes`) are used on the home and game pages and are optional
elsewhere.

## Themes

The colours live in `brand/themes.ts` and reach the site as
`src/styles/tokens.css`, generated by `npm run brand` (never edit it by hand). The site is Daylight,
or Night when the system asks for dark; the header's button switches between
them and `theme.js` remembers the choice in `localStorage`. Without the
script, the site still follows the system. The build refuses any theme whose
text, links or focus ring fall below WCAG AA contrast.

| Token          | Use                                             |
|----------------|-------------------------------------------------|
| `--bg`         | page background                                 |
| `--surface`    | cards                                           |
| `--text`       | body text                                       |
| `--muted`      | secondary text                                  |
| `--border`     | card and table borders                          |
| `--moss`       | links, accents, buttons                         |
| `--river`      | link hover, notes, status                       |
| `--focus`      | the keyboard focus ring                         |
| `--moss-soft`, `--river-soft` | table head, tags, note box (derived) |
| `--mark-*`     | the marks' cells, and the pixel water under the header and above the footer |
